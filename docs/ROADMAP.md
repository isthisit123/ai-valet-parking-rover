## 확인한 것

| 작업 | 확인 범위 |
| --- | --- |
| 로컬 지도 | PNG → OCR 힌트 JSON → 색상 매칭 → 의미 지도. 실제 사진에서 14노드·13간선, 주차칸 6개·건물 2개·출입구 2개. |
| HTTP | ParkingHaeven 화면에서 PNG를 받는 버튼과 수신 서버. 같은 구도의 저장 PNG에서 기존 힌트로 의미 지도 생성 확인. |
| 점유와 경로 | ONNX 점유 JSON 소비와 빈칸 필터. 시험 점유 데이터로 `space_1`을 피하고 `space_2`를 선택. |
| cm 경로 | 픽셀 그래프에서 선택한 경로를 주차칸 중앙까지 이어 cm로 변환한다. 간선 길이와 전체 경로 길이는 변환한 좌표 사이의 거리를 합산해 자동 계산한다. 기본 지도에서 미리보기 5개 생성. 검증된 주행 파일 형식은 자동 시험으로 확인. |

## 수동 입력을 줄일 작업

| 단계 | 현재 입력 | 후속 작업 |
| --- | --- | --- |
| 로컬 지도 생성 | PNG와 시설 이름표. 시설별 픽셀 힌트는 OCR이 생성한다. | HTTP로 받은 새 PNG에도 같은 OCR 흐름을 적용한다. |
| cm 미리보기 | 새 사진에 맞는 `floor_points.json`에 전지 모서리 4개의 픽셀 좌표와 이미지 해시가 필요하다. 전지 크기는 같은 전지에서 재사용한다. | 고정한 빨간 십자를 이용해 새 사진의 보정 입력을 자동 생성한다. |
| 주행용 cm 경로 | 현재 검증은 같은 사진의 전지 모서리 4개와 십자 4개의 픽셀·실측 좌표 쌍을 사용한다. 기본 파일의 `control_points`가 비어 있어 현재 기본 결과는 `world_estimate`다. | 자동 검출한 기준점과 별도로 실측 오차를 확인해 주행용 변환을 검증한다. 검증을 통과하면 주행용 `*_cm.json`이 자동 생성된다. |

### 고정 십자 자동 보정

현재 [보정 코드](../src/map_processing/planar_calibration.py)는 `control_points`에 입력된 `pixel`과 `world_cm` 좌표 쌍으로 Homography를 계산한다. 사진에서 빨간 십자의 교차점을 자동 검출하고 각 실측 좌표와 연결하는 기능은 남아 있다.

1. 전지 위에 빨간 십자 4개를 고정한다. 전지 왼쪽 위를 원점으로 각 십자의 ID와 교차점 실측 `(x, y)` cm 좌표를 한 번 저장한다. 배치가 그대로면 이 값을 재사용한다.
2. 새 사진에서 빨간 도로와 십자를 구분하고, 검출한 교차점의 픽셀 좌표를 각각의 십자 ID에 연결한다.
3. 사진 해시와 픽셀·실측 좌표 쌍을 보정 입력에 기록한다. 이 입력으로 픽셀 → cm 변환을 계산하고 기존 경로 변환과 길이 계산에 연결한다.

## 맵 제작팀

- [ ] HTTP로 받은 PNG를 로컬 OCR 자동 생성 흐름에 연결한다. 새 사진 한 장으로 힌트 JSON과 의미 지도가 만들어지는지 확인한다.
- [ ] 실제 카메라에서 주차칸 영역 6개를 다시 지정하고 빈 배경 사진을 저장한다. 모형 차를 넣고 뺐을 때 해당 칸만 `free → occupied → free`로 바뀌는지 검증한다.
- [ ] 위 기준점 입력 자동화를 적용하고, 선택한 빈칸 중앙에서 끝나는 검증된 cm 경로를 주행팀에 전달한다.

## 주행팀

- [ ] 실제 로버에서 좌우 바퀴의 PWM을 실측해 수신 스케치에 입력한다. 바퀴를 띄운 상태에서 모터 방향, ToF, 통신·추적 유실 시 정지를 확인한다.
- [ ] ArUco 위치·방향을 지도와 같은 월드 cm로 전달한다. 실측 위치에서 좌표와 방향을 대조한다.
- [ ] 짧은 직선에서 출발·정지를 검증한 후 회전·주차칸 진입을 시험한다.

## 합동 시험

- [ ] 한 칸을 점유시켜 로버가 다른 빈칸의 중앙에서 정지하는지 확인하고 오차를 기록한다.
- [ ] 실측 보정을 맞춘 뒤 HTTP 입력에서 cm 경로까지 이어지는 흐름을 확인한다. 현재 웹 버튼의 완료 범위는 의미 지도까지다.
