## 수동 입력을 줄일 작업

| 단계 | 현재 입력 | 후속 작업 |

### 고정 십자 자동 보정

카메라·PNG 입력에서 빨간 십자를 자동 검출하도록 연결했다. 원본 지도 사진의 십자 4개 검출과 합성 원근 영상에서 독립 확인점 오차 검사를 시험했다. 실제 카메라들에서의 재현성과 실측 검증은 남아 있다. [실행 방법](../README.md#카메라에서-빨간-십자-자동-검출)

1. 전지 위에 빨간 십자 4개를 고정한다. 전지 왼쪽 위를 원점으로 각 십자의 ID와 교차점 실측 `(x, y)` cm 좌표를 한 번 저장한다. 배치가 그대로면 이 값을 재사용한다.
2. 새 사진에서 빨간 도로와 십자를 구분하고, 검출한 교차점의 픽셀 좌표를 각각의 십자 ID에 연결한다.
3. 사진 해시와 픽셀·실측 좌표 쌍을 실행 결과에 기록한다. A~D로 계산한 변환을 cm 미리보기에 적용한다. A~D 안쪽의 E는 도로 교점 또는 독립 빨간 십자로 지정하고, 오차가 허용 범위 이내이면 주행용 경로를 생성한다.

### HTTP PNG → OCR 지도 생성 단계

| 단계 | 작업과 완료 기준 | 상태 |
| --- | --- | --- |
| 1. 입력 이미지 확인 | `scripts.check_http_capture`로 수신 PNG의 해시·해상도를 수신 보고서와 대조하고, 같은 이미지로 기존 로컬 OCR 지도 생성을 시험한다. 기본 지도를 보존하며 이름표 10개와 시설 매핑 결과를 별도 폴더에 기록한다. | 구현·기준 PNG와 실제 수신 4:3 사진 검증 완료. |
| 2. 생성 흐름 공통화 | 로컬 PNG·웹캠 실행을 유지하며 HTTP에서도 같은 OCR 생성 흐름을 호출할 수 있게 정리한다. | HTTP가 `scripts.generate_map.generate_map`을 재사용. 기존 로컬·웹캠 회귀 시험 통과. |
| 3. HTTP 연결 | 기존 힌트 변환 대신 공통 OCR 흐름을 호출한다. 실패하면 직전 성공 결과를 보존한다. | 구현·실제 HTTP 전송 검증 완료. 고정 `latest/`를 갱신하고 실패 진단은 `last_failed/`만 갱신. 기본 지도와 직전 성공 결과 보존. |
| 4. 웹 결과 표시 | 성공 결과·파일 링크와 미인식 이름표·실패 원인을 웹에 표시한다. | 표시 구현. OCR 보고서·미리보기 링크와 미인식 ID 안내 추가. 브라우저에서 서버 재시작 후 확인 필요. |
| 5. 통합 검증 | 동일 PNG의 로컬/HTTP 결과, 새 구도, OCR 실패, 중복 요청을 검증한다. 지도 ID·이미지 해시와 결과 파일이 일치해야 한다. | 실제 수신 사진의 로컬/HTTP 생성·다운로드, 종횡비 변경, OCR 실패·원본 보존 검증. 동시 요청과 여러 카메라 구도·조명 추가 검증 필요. |

실행 방법은 [수신 PNG 검사](../README.md#1단계-수신-png로-로컬-ocr-지도-생성-검사)와 [HTTP 캡처 자동 보정](../README.md#같은-http-사진으로-cm-지도-만들기)을 참고한다. `--marker-layout`를 지정하면 같은 원본의 그래프와 픽셀 경로를 써서 cm 결과를 함께 게시한다.

통합 검증에서 기존 실물 PNG를 로컬 HTTP로 보내 RapidOCR로 시설 10개를 인식했다. 연결된 도로 그래프는 14노드·13간선이고, P5 확인점 오차는 0.23cm였다. 픽셀 경로 5개와 주차칸 중앙까지의 cm 경로 5개를 생성했고, cm PNG·JSON 다운로드와 원본 해시 일치를 확인했다. 통합 자동 시험 90개가 통과했다.

자동 시험: `python -m unittest discover -s tests -v` 81개 통과. 가까운 노드 영역이 맞닿을 때의 실제 중심선 간선 복원, 단절 도로를 임의로 잇지 않는지, 평행 간선 보존, 회색 바닥과 검은 시설 분리, 어두운 초록색 검출, 이름표 누락, 수신 해시·해상도 불일치, 종횡비 변경, 원본·기본 지도 보존을 확인했다. 자동 시험에서는 OCR 응답을 고정하며, 실제 HTTP 시험은 수신 사진 `20261116T101948_080510Z_44b1e9da/source.png`와 RapidOCR를 사용했다. 재전송 성공 결과는 `20261116T102750_197422Z_63f0e125/`에 보관한다.

이번 실패 원인과 수정: 웹은 기존 카메라 비율·힌트에서 중단됐고, 로컬 OCR에서는 맞닿은 노드 영역의 연결 간선 누락 및 회색 바닥과 시설의 색상 병합이 확인됐다. `graph_exporter`에서 실제 중심선 접촉 간선을 보존하고, 미매칭 검은 시설에만 더 어두운 기준의 재검출을 추가했다. 도로 연결·시설 일대일 매칭 검사 자체는 유지한다.

추가 조명 사례: `20261116T103142_894981Z_33d5f2c1/source.png`에서 B의 전체 프레임 OCR 검출이 누락되고 기본 검은 시설 후보도 바닥과 합쳐져 보완 OCR에 들어가지 못했다. `scripts/ocr_buildings.py`에도 시설 매칭과 같은 어두운 후보 재검출을 적용했다. 이후 확인된 P1의 밝기 누락은 실물 사진용 초록색 V 하한을 90으로 분리해 보완했다. 실제 HTTP 재시험에서 B는 `bright_text_patch`로 `B`(점수 0.99991)로 읽혔고, 시설 10개·16노드·15간선·연결 정상으로 생성됐다. 결과는 `20261116T103701_805026Z_85db1327/`에 보관한다. 기존 ID 규칙과 신뢰도 기준은 유지한다.

웹 경로 시험: 촬영 사진 `20261116T103906_030958Z_d4a3c7cc/source.png`를 실제 HTTP·RapidOCR로 재처리해 `20261116T104501_121931Z_2baf31bd/routes/`에 5개 PNG·JSON을 생성했다. 선택 결과는 조건 순서대로 P1/P3/P4/P3/P6이며, 모든 JSON의 사진 해시·지도 ID·ID 버전과 도로 영역·8방향 연속성, 10개 파일의 HTTP 다운로드를 확인했다. 두 번째 조건에서 도로 이탈 오류를 주입한 자동 시험에서는 지도 보존·경로 실패 구분·부분 결과 미게시를 확인했다. Node에서 브리지 문법과 DOM 모의 실행으로 5개 미리보기·10개 저장 링크 및 실패 시 이전 링크 제거를 확인했다. 이 연결 작업에서는 기존 경로 알고리즘을 수정하지 않았다.

### 다른 PC에서 최신 지도 받기

고정 저장 갱신: 사용자 요청에 따라 새 HTTP 결과는 `data/http_map_captures/latest/`의 원본·지도·5개 경로·OCR 고정 파일에 덮어쓴다. 실패는 `last_failed/`만 교체하고 직전 성공은 유지한다. 생성·게시 중 오류의 롤백과 반복 성공/실패 시 폴더가 누적되지 않는지 자동 시험으로 확인했고, 실제 사진으로 `latest/` 생성 및 고정 URL 다운로드도 확인했다. 과거 회차 폴더는 보존한다. 아래 LAN 조회 기능은 여전히 별도 작업이다.

1. 카메라가 연결된 PC에서 웹캠으로 촬영한 뒤 OCR과 지도 생성을 실행한다. 검증에 성공한 최신 PNG와 `graph.json`, `semantic.json`을 같은 LAN에서 HTTP로 조회할 수 있게 한다.
2. 받는 PC에서 주기적으로 최신 지도를 조회한다. `map_id`와 `map_image_sha256`으로 새 버전을 구분하고, 해당 버전의 PNG와 JSON이 일치할 때 화면을 갱신한다.
3. 카메라 PC에서 다시 촬영했을 때 받는 PC에 새 지도가 자동으로 반영되는지 확인한다. OCR이나 지도 생성에 실패한 회차에는 직전 성공 지도가 계속 조회되는지 확인한다.
