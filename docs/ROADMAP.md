## 확인한 것

| 작업 | 확인 범위 |
| --- | --- |
| 로컬 지도 | PNG → OCR 힌트 JSON → 색상 매칭 → 의미 지도. 실제 사진에서 14노드·13간선, 주차칸 6개·건물 2개·출입구 2개. |
| HTTP | ParkingHaeven 화면에서 PNG를 받는 버튼과 수신 서버. 같은 구도의 저장 PNG에서 기존 힌트로 의미 지도 생성 확인. |
| 점유와 경로 | ONNX 점유 JSON 소비와 빈칸 필터. 시험 점유 데이터로 `space_1`을 피하고 `space_2`를 선택. |
| cm 미리보기 | 같은 기본 지도 기준 미리보기 5개 생성. 다른 사진·이전 칸 ID 버전의 입력 거부. 검증된 주행 파일 형식은 자동 시험으로 확인. |

## 맵 제작팀

- [ ] HTTP로 받은 PNG를 로컬 OCR 자동 생성 흐름에 연결한다. 새 사진 한 장으로 힌트 JSON과 의미 지도가 만들어지는지 확인한다.
- [ ] 실제 카메라에서 주차칸 영역 6개를 다시 지정하고 빈 배경 사진을 저장한다. 모형 차를 넣고 뺐을 때 해당 칸만 `free → occupied → free`로 바뀌는지 검증한다.
- [ ] 사용할 PNG에서 실측 기준점 4개를 등록한다. 다른 바닥 지점으로 변환 오차를 확인하고, 선택한 빈칸 중앙에서 끝나는 검증된 cm 경로를 주행팀에 전달한다.

## 주행팀

- [ ] 바퀴를 띄운 상태에서 좌우 모터 방향과 PWM, ToF, 통신·추적 유실 시 정지를 확인한다.
- [ ] ArUco 위치·방향을 지도와 같은 월드 cm로 전달한다. 실측 위치에서 좌표와 방향을 대조한다.
- [ ] 짧은 직선에서 출발·정지를 검증한 후 회전·주차칸 진입을 시험한다.

## 합동 시험

- [ ] 한 칸을 점유시켜 로버가 다른 빈칸의 중앙에서 정지하는지 확인하고 오차를 기록한다.
- [ ] 실측 보정을 맞춘 뒤 HTTP 입력에서 cm 경로까지 이어지는 흐름을 확인한다. 현재 웹 버튼의 완료 범위는 의미 지도까지다.
