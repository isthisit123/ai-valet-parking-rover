# Q-ROVER AI 발렛파킹 — 개발 로드맵

> 마지막 대화 기준: **2026-11-09**  
> 전체 시스템 목표는 `../README.md`, 상세 기술·실행 로그는 `PROJECT_HANDOFF.md` 참고.  
> 아래 체크 여부는 **대화에서 실제 확인된 실행 결과**를 바탕으로 작성했으며, Codex가 로컬 코드를 점검하면서 갱신한다.

## 프로젝트 범위

**지도·경로 담당의 1차 완료 기준:**

규칙 기반 지도 이미지 → 도로/주차칸/건물/출입구 분석 → 의미 포함 그래프 JSON → 조건별 주차칸 선택 → 다익스트라 최단 경로 → **지도 위 경로 시각화 + 연속 waypoint 데이터 제공**.

**실물 통합 단계:** 카메라 캘리브레이션, 공통 월드 좌표계, Homography, ArUco 로버 위치·방향 추정과 주행 제어 연결.

**역할 분리:** 차량 YOLO 인식/주차 점유 판정은 다른 팀원이 담당. LLM/VLM은 선택적 후순위.

## Phase 1. 지도 처리 기초 — 완료(지도 2종의 기본 테스트)

- [x] OpenCV HSV 기반 빨간 도로 마스크 검출
- [x] 노이즈/작은 연결 영역 제거
- [x] Skeletonization으로 도로 중심선 추출
- [x] 8-이웃 기반 끝점·교차점 검출
- [x] 중심선 픽셀 그래프 및 최종 가중치 그래프 생성
- [x] 노드·간선·픽셀 단위 거리·간선별 `path`를 JSON 저장
- [x] 일반/장애인 주차칸, 건물 2개, 입구·출구 색상 영역 검출
- [x] 지도별 힌트 좌표로 건물 A/B와 입구/출구 의미 연결
- [x] 주차 조건별 후보 선택 및 다익스트라 경로 계산
- [x] 첫 번째 지도 테스트: 12 nodes, 11 edges, connected=True, 시설 4/2/2/2
- [x] 두 번째 지도 테스트: 12 nodes, 11 edges, connected=True, 시설 4/2/2/2, 경로 실행 성공

### 검증 범위의 한계

- 검증된 두 지도는 **동일한 도형/색상 규칙**과 비교적 단순한 도로 구조를 사용함.
- 복잡한 순환 도로, 붙어 있는 교차점, 고립 도로망, 불규칙 곡선/대각선 등은 추가 테스트 필요.
- 지도마다 출입구의 노드 번호가 달라졌으므로 `N번호` 기반 하드코딩 금지.
- 원본과 두 번째 지도는 각각의 이미지·라벨 파일로 보존하며, 실행 시 지도 ID로 선택할 수 있음.

## Phase 3. 최단 경로 시각화 및 주행 경로 데이터 — 다음 단계

- [ ] `parking_selector`가 선택한 경로의 **모든 실제 그래프 간선**을 추출
- [ ] 각 간선의 `path`를 진행 방향에 맞게 연결해 전체 `waypoints` 생성
- [ ] 간선의 `from→to` 방향, 연결부 중복 점, 비정상 픽셀 도약 검사
- [ ] `nx.MultiGraph`의 복수 간선 중 최단 경로가 사용한 간선을 정확히 선택
- [ ] 원본 지도 위에 시작점/도착점/도로 중심선 경로 강조 표시
- [ ] 선택 조건별로 미리보기 PNG와 waypoint 포함 JSON 저장
- [ ] 주차칸 고유 ID, 총 거리, 픽셀 좌표계/단위와 함께 출력
- [ ] 기존 두 지도에서 시각적 경로 검증 및 테스트 추가

**완료 기준:** 출입구/건물 조건별로 선택된 주차칸까지의 경로가 지도에서 올바르게 표시되고, 로버 담당 팀원이 사용할 수 있는 연속 좌표 목록을 추출할 수 있다. 이 단계까지가 **실물 통합 이전 지도·경로 모듈의 1차 완료 기준**.
