# ROADMAP.md — AI Valet Parking Rover 팀 전체 개발 계획

> **정리 기준:** 2026-11-10 · 자세한 담당 업무/팀 인터페이스: [TEAM_GUIDE.md](TEAM_GUIDE.md)  
> 체크는 **대화로 확인된 과거 실행 기록**과 예정 작업을 구분한다. 팀원의 실제 최신 진행 상황은 코드와 PR·테스트 결과로 갱신한다.

## 현재 위치

- **확인된 완료:** 기존 색상 규칙 기반 지도 2종의 기본 도로 그래프·시설 인식·조건별 Dijkstra 실행.
- **지도 담당의 최근 우선 작업:** **주차칸 고유 ID(`P01` 등)와 bbox/도로 노드 매핑**. Codex 작업 요청은 준비되었으나 최신 로컬 구현·완료 여부는 확인 필요.
- **병렬 착수 가능:** YOLO 데이터 수집/인식 방식 검토, Q-ROVER 모터·센서 단독 시험, 실물 배치/카메라 준비.
- **지도 ID 안정화 이후:** 코드 리팩토링 → 최단 경로 시각화/waypoint → 카메라 좌표계 통합.
- **최종 통합:** 점유 `free` 칸 선택 → 경로 추종 → 도착 확인.

## Stream A — 지도·경로 담당

### A1. 지도 처리 기초 — 기본 검증 완료
- [x] 빨간 도로 HSV 검출, 잡음 제거, Skeletonization
- [x] 8-이웃 기반 끝점·교차점, 픽셀 그래프, 최종 가중 MultiGraph
- [x] 일반/장애인 주차칸, 건물, 입구·출구 영역 및 힌트 매핑
- [x] `entrance`, `exit`, `building_a`, `building_b` 조건 선택/Dijkstra 실행
- [x] 원본 지도: 노드 12, 간선 11, connected=True, 시설 일반 4/장애인 2/건물 2/게이트 2
- [x] 테스트 지도: 동일 수량 및 조건별 최단 경로 실행

**범위 한계:** 두 단순 지도만 검증. 루프/근접 교차점/자유곡선/다중 도로망 일반화 검증은 아직 필요.

### A2. 주차칸 ID와 위치 매핑 — 우선 작업
- [ ] 실제 `semantic_mapper.py`와 라벨 JSON 스키마 확인
- [ ] 일반/장애인 주차칸에 `P01` 등 고유 ID 부여, `bbox`, `center`, `road_node_id` 저장
- [ ] 동일 주차칸 재인식 시 ID 유지: 지도/시설 위치 힌트 등 안정적 매핑 설계
- [ ] `map_id`별 ID 중복·오매칭 검증, 도로 `N번호` 변동과 분리
- [ ] 원본 지도/보존된 테스트 지도 회귀 실행
- [ ] YOLO 팀에 실제 샘플 JSON/좌표계 명세 전달

**완료 기준:** 재처리해도 동일 위치 주차칸 ID가 유지되고 기존 4가지 선택 조건 결과가 깨지지 않음.

### A3. 지도 코드 리팩토링
- [ ] 원본 지도와 테스트 지도 입력·출력 분리, 덮어쓰기 방지
- [ ] HSV/영역/교차점 반경 등 하드코딩 설정 분리
- [ ] 지도 읽기·도로 그래프·의미 매핑·선택·경로 책임 정리
- [ ] ID/시설/간선 `path` 방향/연속성 검증 및 명시적 오류 처리
- [ ] 변경 전후 두 지도 기본 결과 비교 자동화

### A4. 최단 경로 시각화·waypoint
- [ ] `nx.MultiGraph`의 실제 선택 간선을 따라 `edge.path` 추출
- [ ] 방향 맞춤, 연결부 중복/도약 처리, 전체 연속 waypoint 생성
- [ ] 원본 지도 위 선택 경로/시작·목표 PNG 출력
- [ ] 경로 JSON에 `map_id`, `parking_space_id`, 좌표 프레임, 단위, 거리 포함
- [ ] 네 선호 조건과 두 지도에서 시각/데이터 검증

**실물 통합 전 지도 팀 1차 완료 기준:** 고정 ID를 가진 빈 주차칸을 지정하면 그래프 경로·픽셀 waypoint가 정확히 산출됨.

## Stream B — YOLO 점유 인식 담당 (지도 작업과 병렬 진행)

- [ ] 차량 객체 검출 vs 주차칸 ROI free/occupied 분류 방식 결정
- [ ] 실제 카메라 시점에서 빈칸·점유·다양한 차량 배치와 조명 데이터 수집
- [ ] 라벨링과 train/validation/test 분리, 모델 학습·평가
- [ ] 미검출/장애물/불확실 상황 `unknown` 정책 정의
- [ ] 카메라 bbox/ROI와 지도 `parking_space_id` 정합 방법 합의
- [ ] 점유 JSON(`map_id`, ID, `status`, `observed_at`, `confidence`) 샘플·테스트 제공
- [ ] mock occupancy와 실제 검출 결과로 selector 통합 시험

**완료 기준:** 카메라 영상에서 주차칸별 상태를 전달하고, 불확실함을 빈칸으로 오인하지 않음.

## Stream C — Q-ROVER 주행·제어 담당 (병렬 진행)

- [ ] UNO Q와 모터 기본 연결/제어 시험, 안전 정지 구현
- [ ] 로버 실측 폭·회전반경·가능 속도·엔코더 유무 확인
- [ ] ToF 전방 장애물 검출 및 통신/명령 타임아웃 정지
- [ ] 공통 월드 waypoint/로버 pose 입력 계약 설계
- [ ] 직선→회전→연속 waypoint 추종 구현
- [ ] 주행/도착 상태를 상위 모듈에 전달
- [ ] ArUco 인식 유실·목표 칸 점유 변경에 대한 안전 정책 검증

**완료 기준:** 제어/센서 단독 시험 통과 후, 실제 좌표 경로의 안정적 추종 및 도착 판정.

## Stream D — 실물·카메라·좌표계 (협업 담당 결정 필요)

- [ ] 모형 주차장 배치 확정: 약 **636×939 mm 전지 사용 계획**, 로버 폭/통로 폭과 색 테이프 검토
- [ ] 현재 디지털 지도 색 규칙과 실물 제작 색 차이 확인. **일반 주차칸 초록색 변경은 검토안**이며 확정/코드 반영은 검증 후
- [ ] 천장 카메라 모델/높이/고정 방식 확정 (앱코 APC850은 후보)
- [ ] 카메라 렌즈 왜곡 보정 + 바닥 평면 기준점 검출
- [ ] 지도 픽셀→월드와 카메라 픽셀→월드 Homography 분리 구현
- [ ] ArUco 마커 위치/방향·높이·로버 중심 오프셋 처리
- [ ] 로버 자세 `(x,y,θ)` 추적 오차/지연 테스트
- [ ] 월드 cm에서 경로 길이 재계산, 제어 팀과 좌표계 합의

**완료 기준:** 지도 목표점과 카메라 로버 위치를 하나의 월드 좌표계에서 비교 가능.

## Stream E — 통합·시연

- [ ] 모듈 간 JSON 스키마/상태 갱신 주기/버전 합의
- [ ] **가짜 점유 데이터**로 이미 주차된 칸 제외되는지 먼저 시험
- [ ] 실제 YOLO 결과를 `parking_space_id`와 매칭, `free`만 선택
- [ ] 주차 조건→Dijkstra→월드 waypoints→제어 명령 연결
- [ ] 전체 주행 안전성: ToF, 마커 미검출, 통신 두절, 목표 칸 재점유
- [ ] 반복 시연: 주차 성공/오차/시간/예외 로그 저장
- [ ] README 및 데모 실행 절차 갱신

## 공통 마일스톤

| 순서 | 공유 결과물 | 선행 조건 |
|---|---|---|
| M1 | 지도 주차칸 고유 ID + bbox/도로 노드 샘플 | 지도 Stream A2 |
| M2 | YOLO 점유 상태 JSON + 독립 평가 | B 진행, M1의 ID 규약 합의 |
| M3 | 지도 경로 시각화 + 픽셀 waypoint | A3/A4 |
| M4 | 월드 좌표 계약 + 로버 제어 기본 시험 | C/D 병렬 진행 |
| M5 | 빈 주차칸 선택 → 목표 주행 → 도착 검증 | M1~M4 연결 |

**체크박스 갱신 규칙:** 팀원이 PR/테스트 결과를 제시하면 완료 처리. 과거 로그에 있던 성공을 다른 지도·실물 테스트의 성공으로 확대 해석하지 않는다.
